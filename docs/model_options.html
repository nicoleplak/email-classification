Email classifier · Replacing GPT-4.1 · 26 Nov 2026

Which models after GPT-4.1

Options for the three model steps of the classifier, with cost per email at our own prompt sizes, expected time per email, and what the code has to change. Prices are Azure Global Standard list prices from public sources and must be confirmed on the Azure pricing page before a decision.

Recommendation

GPT-6.1 Terra with reasoning off for the category and the customer details, GPT-6 Luna for attachment summaries, and a second opinion from GPT-6 Sol (reasoning low) only for the emails where Terra's five answers disagree. About 25% cheaper than GPT-4.1 today at about the same speed, deployed in the EU Data Zone.

Do not run gpt-6-sol with its default reasoning on every step: about 4× the cost of today and 2 to 4× slower, without a measured gain. Before committing, run the benchmark in the last section on the 70 copied emails: two facts (below) can only be settled by calling the deployments.

The options

A · Today: GPT-4.1

Five answers in one call with token probabilities. The reference for cost and quality. Stops working when 4.1 is retired.

B · gpt-6-sol as set on your laptop

Medium reasoning on every step, five separate calls for the vote. Highest cost, slowest; one 45-minute run would classify about a third of today's number.

C · GPT-5.1, reasoning off

Closest to today: the same call shape may work. Cheaper input, dearer output. A generation behind GPT-6, and token probabilities may not come back with a JSON schema.

D · Terra + Luna + Sol on doubt (recommended)

Terra with reasoning off gives five answers in parallel; the % is the share that agree. Luna summarizes attachments. When the five disagree (about 1 in 5), Sol with low reasoning gives the reviewer a better proposal. The email still goes to review, so Sol never makes an email automatic on its own.

E · Luna everywhere

Very cheap and fast. Small models miss subtle Greek wording and rule exceptions, so more emails would go to review or be wrong. Useful as a lower bound in the benchmark.

F · Sol (low) everywhere

The quality ceiling at a sensible effort. About twice today's cost. Worth it only if the benchmark shows clearly more correct categories than D.

Two things only a test can answer

  • Do Terra and Sol accept several answers per call (n=5) and token probabilities with reasoning off and a JSON schema? Reports conflict: GPT-5.1 and 5.2 return empty probabilities with a JSON schema. If n is refused, the code sends five calls in parallel instead. The fixed 14,400-token prefix is cached, so this adds about 10% to the cost, not 5×.
  • Which models your Azure resource can deploy in the EU Data Zone, and with how much quota. Five parallel answers of 17,000 tokens for 90 emails in 45 minutes needs about 170,000 tokens per minute on the category deployment.

The retirement date is also unclear in public sources (October 2026, January 2027 for OpenAI's own API, April 2027 in Azure's schedule). Check the date shown on your deployment in the Foundry portal; if it is January, the plan below fits.

What changes in the code

  1. One deployment setting per step in .env and the job: category, attachments, customer details, second opinion, each with its reasoning effort. Today all three steps share AZURE_OPENAI_DEPLOYMENT.
  2. Model-aware calls: max_completion_tokens instead of max_tokens; temperature and logprobs only where the model accepts them; n=5 or five parallel calls.
  3. Certainty from votes when probabilities are missing: the share of the five answers on the winning category (the app already stores the votes). Re-tune the 90% and 80% thresholds on reviewed emails, using the certainty bands in the Statistics tab.
  4. Second opinion on disagreement, recorded on the email so reviewers and the statistics see which model proposed what.
  5. Benchmark tool: tools/model_benchmark.py runs the same emails through each option without saving cases, and writes time, tokens, cost (from the model's own usage numbers) and agreement with reviewed categories to an Excel file.

Plan to January

  1. Deploy Terra, Luna and Sol in the EU Data Zone on openai-data-llm (or check which exist; gpt-6-sol already does).
  2. Code changes 1 to 3 and the benchmark tool, tested locally on the 70 copied emails and on reviewed emails from the review app.
  3. Compare A, C, D, E, F; choose; set the thresholds.
  4. Run the chosen option next to GPT-4.1 for a week (shadow: results stored, not used) before switching the job.
